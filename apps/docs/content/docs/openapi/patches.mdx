MarzbanSDK vendors `packages/sdk/openapi/openapi.json` in the repository instead of fetching Marzban's spec at build time (see [ADR-0003](https://github.com/Ilmar7786/marzban-sdk/blob/main/docs/adr/0003-vendored-openapi-spec.md)), and hand-patches schemas that upstream leaves under-specified. Every patch currently applied is listed here.

## Under-specified schemas no longer drop fields on parse

Several upstream schemas are declared with no `properties` at all — proxy settings, parts of the core config. [kubb](https://kubb.dev) generates these as an empty Zod object, and Zod's default strip mode silently drops every key when parsing a real payload:

- `getCoreConfig()` / `modifyCoreConfig()` returned `{}` instead of the actual Xray core config.
- Every user response's `proxies` field returned `{}` instead of the per-protocol settings.

**Fix (2026-08-12):** patched the schema to `additionalProperties: true`, so kubb emits `.catchall(z.any())` instead of a key-dropping strict object.

| Schema | Where it shows up |
|---|---|
| `ProxySettings` | `user.proxies[protocol]` on every endpoint that returns a user — see the patched-endpoint badges on the [OpenAPI Spec](/docs/openapi/spec) page |
| Core config (GET response) | `GET /api/core/config` |
| Core config (PUT request + response) | `PUT /api/core/config` |

<Callout type="info">
  Pinned by [`gen-regression.test.ts`](https://github.com/Ilmar7786/marzban-sdk/blob/main/packages/sdk/src/gen-regression.test.ts) — a future `pnpm --filter marzban-sdk codegen` run that reverts this fails the test suite instead of shipping silently-truncated data.
</Callout>
