# ADR-0002: Generate the API client with kubb

Status: Accepted
Date: 2025-08-20

## Context

The client was generated by the Java-based `openapi-generator-cli`
(`typescript-axios` template), wrapped in a forked mustache template so
generated methods returned `data` directly instead of an `AxiosResponse`.
The fork needed manual upkeep on every generator upgrade, there was no Zod
schema generation, and operations weren't grouped by OpenAPI tag.

## Decision

Switch generation to [kubb](https://kubb.dev), configured to return `data`
directly (`dataReturnType: 'data'`), emit matching Zod schemas alongside
TypeScript types, and group generated files by tag — all as native plugin
options, with no forked template.

## Consequences

- Dropped the JVM toolchain dependency and the maintenance cost of a forked
  generator template.
- Generated output gained runtime-validated Zod schemas for free, which the
  hand-written client layer now relies on for request/response validation.
- kubb's output shape has changed twice since (see
  [ADR-0004](./0004-classed-generated-api-clients.md)) — the generator
  choice has been stable, its configuration has not.
